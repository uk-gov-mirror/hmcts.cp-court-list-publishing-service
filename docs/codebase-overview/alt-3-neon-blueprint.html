PANEL 01 // SYSTEM OVERVIEW

System Overview

This unit is an HMCTS Modern by Default Spring Boot 4 service from service-hmcts-crime-springboot-template — explicitly not a CQRS/event-sourced cpp-context-* WildFly context. No Maven, no RAML, no event store; one deployable, one status table, contract-first REST.

Function: on an authorised request (permission: Publish Magistrate Court List), pull the court-list payload from Progression, transform it into the CaTH (Court and Tribunal Hearings) document format, sanitize + schema-validate it, transmit it to CaTH through Azure APIM, render a PDF via the Document Generator, and store the PDF in Azure Blob Storage for download. Controllers implement interfaces generated from api-cp-crime-court-list-publisher:0.1.22 — routes are never hand-rolled.

PANEL 03 // SIGNAL FLOW

Signal Flow — One Publish Request

01
INGRESS. POST /courtlistpublishing-service/courtlistpublish → CourtListPublishController (implements generated CourtListPublishApi). Filter chain: JWTFilter → auth-rules filter (permission Publish Magistrate Court List). CJSCPPUID header mandatory.
02
STATUS REGISTER. CourtListPublishStatusService.createOrUpdate upserts court_list_publish_status (court centre / list type / date range) → courtListId.
03
ASYNC HANDOFF. CourtListTaskTriggerService enqueues PUBLISH_AND_PDF_GENERATION_TASK via task-manager-service. HTTP returns immediately.
04
FETCH. Task executor reads jobData → CourtListQueryService → Progression query API for the raw CourtListPayload.
05
TRANSFORM. Strategy by CourtListType: Standard / OnlinePublic transformation service, enriched via ReferenceDataService (courtrooms, LJA / enforcement area).
06
SCRUB + VALIDATE. CourtListDocumentSanitizer (HTML strip, WAF patterns, RequiredStringFieldsRegistry) → JsonSchemaValidatorService against standard-court-list-schema.json / online-public-court-list-schema.json.
07
TRANSMIT. CaTHService / CaTHPublisher → CaTH via APIM. Gated by cath.publishing-enabled; StubCourtListPublisher substitutes when off.
08
RENDER + STORE. CourtListPdfHelper → DocumentGeneratorClient renders PDF → AzureBlobService uploads to blob container (Azurite locally).
09
EGRESS. Status → PUBLISH_SUCCESSFUL; FileController + CourtListDownloadService stream CourtList.pdf on demand.

PANEL 05 // HAZARD NOTES

Hazard Notes

  • README is largely the template's README and references a docs/ directory that doesn't exist. build.gradle is the source of truth.
  • No runIntegrationTests.sh. Workspace CQRS conventions don't apply. ITs: gradle integration. Caution: gradle build runs them too (build → check → integration).
  • Docker daemon must be up first — checkDockerDaemon fails fast. Port map: app 8082, debug 8787→5005, WireMock 8089, Postgres 55432, Azurite 10000.
  • composeDown intentionally not finalized — stack persists post-run for inspection; next composeUp recreates.
  • Committed Azurite key = Microsoft's public dev key (# gitleaks:allow). Not a leak. Do not rotate.
  • Compile is -Werror; PMD ruleset gates PRs; CodeQL + secrets-scanner also run.
  • Version drift: CI pre-pulls azurite:3.33.0, compose runs 3.34.0. Harmless — pre-pull is cache-warming only.
  • Feature flags everywhere: CP_CLP_AUTHZ_ENABLED, CP_CLP_AUDIT_ENABLED, CATH_PUBLISHING_ENABLED. ITs run authz/audit OFF, CaTH ON → WireMock.

IT execution model on the runner

ubuntu-latest ships Docker + Compose v2, so the same Avast docker-compose Gradle plugin that runs locally also runs in CI — laptop and runner share one compose file:

  ├─ composeBuild + composeUp      // docker compose up --wait --wait-timeout 120
  │    ├─ app      :8082           // SPRING_PROFILES_ACTIVE=integration, authz/audit OFF
  │    ├─ db       :55432          // postgres:16-alpine (healthcheck-gated)
  │    ├─ wiremock :8089           // progression / refdata / CaTH / docgen stubs

// captureContainersOutput=true → app logs interleave into the Gradle/Actions job log

Dedicated IT workflow (drop-in)

name: Integration Tests
on:
  pull_request: { branches: [ main ] }
  workflow_dispatch:

jobs:
  integration:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-java@v5
        with: { distribution: temurin, java-version: '21' }
      - uses: gradle/actions/setup-gradle@v5
        with: { gradle-version: current }
      - name: Warm image cache              # optional anti-flake measure
        run: |
          docker pull postgres:16-alpine
          docker pull wiremock/wiremock:3.9.1
          docker pull mcr.microsoft.com/azure-storage/azurite:3.34.0
      - name: Run integration tests
        run: gradle integration
      - name: Tear down stack
        if: always()                        # Gradle leaves stack up by design
        run: docker compose -f docker/docker-compose.integration.yml down -v
      - name: Upload IT report
        if: always()
        uses: actions/upload-artifact@v5
        with: { name: integration-test-report, path: build/reports/tests/integration }

Failure triage protocol

  • Container logs are already in the Actions job log (capture is on) — read the app's stack trace there first.
  • If composeUp failed: check the 120 s --wait budget vs the app healthcheck on /courtlistpublishing-service/actuator/health.
  • Download build/reports/tests/integration artifact for the HTML report.
  • Reproduce locally with the identical command — the compose stack is environment-invariant.
